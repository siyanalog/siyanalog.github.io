Radio Receiver

A Linux-based software-defined radio receiver in C++ designed to continuously process and decode 1090 MHz ADS-B transmissions from an RTL-SDR.

C++ Linux RTL-SDR GNU Radio DSP

The receiver operates around the 1090 MHz ADS-B band and processes a continuous stream of complex I/Q samples from the RTL-SDR. It supports both live SDR input and prerecorded I/Q files through a shared sample-source interface.

GNU Radio is used as a reference and visualization environment for validating filters, spectrum behavior, and recorded RF captures.

Raw samples are processed through a custom C++ DSP pipeline consisting of:

  • I/Q normalization and power estimation
  • noise-floor estimation
  • ADS-B preamble detection
  • symbol synchronization
  • pulse-position demodulation
  • FFT-based spectrum analysis

Detected transmissions are converted into 56-bit or 112-bit Mode-S frames and validated using CRC checks

Autonomous Satellite Tracking Station

An autonomous satellite tracking station designed to predict satellite passes, track selected targets using a closed-loop pan-tilt system, and expose live tracking telemetry through a web interface.

STM32 ESP32 FreeRTOS PWM UART

The system uses satellite orbital data, ground-station position, and precise timing to calculate the azimuth and elevation of selected satellites during visible passes.

A tracking state machine manages the platform through idle, pre-positioning, acquisition, tracking, and parking, while generated pointing commands are applied to the pan and tilt axes through closed-loop motion control.

A web interface provides access to the satellite watch list, upcoming passes, predicted and measured pointing angles, tracking error, and overall system status.

The system uses an STM32 running FreeRTOS for real-time tracking and motion control, paired with an ESP32 running ESP-IDF for networking and the web interface.

  • FreeRTOS tasks for satellite tracking, trajectory generation, motor control, communication, and diagnostics
  • Encoder-based closed-loop pan and tilt control
  • Hardware timer-based PWM motor control
  • UART communication between the STM32 and ESP32
  • ESP32-based Wi-Fi connectivity and live web telemetry
  • Tracking state management, homing, position limits, and fault handling

A Python-based test environment is used to simulate satellite trajectories and validate firmware behavior under conditions such as encoder noise, communication errors, actuator delay, and connectivity loss.

Wireless Telemetry Platform

A low-level embedded telemetry platform designed to continuously collect, timestamp, and log nearby Wi-Fi and Bluetooth activity.

ESP32 FreeRTOS SPI UART I²C

The platform collects multiple telemetry sources concurrently, including GNSS position and timing data, Wi-Fi and Bluetooth scan results, and system power measurements.

Telemetry is timestamped, passed through bounded FreeRTOS queues, and written to an external microSD card. The system is designed for continuous operation with predictable memory usage and mechanisms for detecting data loss, queue saturation, and peripheral failures.

The firmware is developed in C using ESP-IDF and FreeRTOS on an ESP32-S3-WROOM development board.

  • GNSS acquisition over UART with PPS-based timing
  • Wi-Fi and Bluetooth Low Energy scanning
  • INA226 power and current monitoring over I²C
  • External microSD logging over SPI using a binary log format with CRC validation
  • Concurrent FreeRTOS tasks for acquisition, processing, and storage
  • Bounded queues and fixed-size buffers for predictable memory usage

FPGA Digital Downconverter

A hardware digital downconverter implemented on a PYNQ-Z1 FPGA to select a frequency channel from a wider-band signal and output filtered baseband I/Q data.

SystemVerilog PYNQ-Z1 Vivado Cocotb Python

Simulated multi-channel radio signals are generated in Python and streamed to the FPGA. The FPGA tunes to a selected frequency, shifts the channel to baseband, filters unwanted frequency content, and outputs I/Q samples for further SDR processing.

The project implements one complete and independently testable signal-processing subsystem that can later be integrated into a larger SDR receiver.

The FPGA datapath implements an NCO, complex mixer, and FIR filter to tune to a selected frequency, shift it to baseband, and isolate the desired channel.
